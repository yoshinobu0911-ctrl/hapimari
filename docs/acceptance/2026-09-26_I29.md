## 前提

- **snapshot の再生成コマンドは以後 `pnpm exec supabase db dump --local -s public -s storage -s private -f supabase/schema.generated.sql`**（`-s private` を付けないと private の定義と権限が消える）。
- Edge Runtime 起動のため `abuse_words.ts:8` を一時的に `.ts` 付きにした（コミットしていない）。
- DB の一時変更（blocks の挿入・削除、それに伴う user_events の block_created 2行、004→018 のいいね）はすべて戻し、user_events 4件・blocks 0件・SQL 全スイート合格を確認した。

## 翌朝オーナーに見てほしい点

- **本番反映の順序が重要**: ① Edge Functions（like・agora-token。I28 入り）をデプロイ → ② migration を適用（I08 → I11 → I29 の順） → ③ アプリ配信。I28 より先に I29 を入れると、障害時にトークンが発行されうる。
- 本番適用後、Supabase 管理画面「API → Exposed schemas」に private が**含まれていない**ことを確認する。
- 管理画面の SQL エディタで `select is_blocked_between(x,y)` を直接実行すると forbidden になる。運用で調べるときは `private.is_blocked_between` を使う。
