# ハピマリ UI刷新 デザイナー向け要件定義書

作成日: 2026-07-07 ／ 発注元: 株式会社BYY（オーナー: 中村） ／ 版: v1.0（ドラフト・オーナー確認前）

> **この文書の目的**: 現在エンジニアの仮デザインで動いているマッチングアプリ「ハピマリ」のUIを、
> 外部デザイナーに刷新していただくための要件定義書です。この1本で、プロダクトの狙い・現状・
> 制約・納品物・スコープが分かるようにしています。
> スクリーンショット一式は同じフォルダの `designer_brief_assets/` にあります。

---

## 1. プロダクト概要とポジショニング

### 1.1 ハピマリとは

- **中高年（45〜65歳）の男女向けの、再婚・パートナー探しマッチングアプリ**です。
- 登録できるのは 女性35歳以上・男性45歳以上（上限なし）。中核ユーザーは45〜65歳の男女ですが、
  40歳前後の女性会員も一定数いる想定です。
- 価値観の一致（「家族との時間を大切にしたい」「まずはランチから」等のタグ）でお相手を
  見つけることが商品の核です。**離婚歴・子どもの有無といった事情で第一印象を決めさせない**
  設計思想を持っています（一覧では見せず、詳細画面で伝える）。
- 差別化機能は「デート移行支援」: メッセージが10往復続いたら、アプリが日程調整まで
  そっと後押しする機能です。

### 1.2 ここを間違えないでほしい（ポジショニング）

- **「バツイチ・子持ち特化アプリ（marrish型）」ではありません。** あくまで「中高年向け」が主語です。
- 若年向けの恋活アプリ（Tinder/タップル的な世界観）でもありません。
- トーンの軸は **「落ち着き・安心感・誠実さ」**。
  「人生の後半を、いっしょに歩む人と。」がウェルカム画面のキャッチコピーです。

### 1.3 ビジネスモデル（デザインに影響する範囲のみ）

- 収益は**男性の月額課金が先行**。女性は当面無料。
- 将来、**女性向けの少額プレミアムプラン（500円/月想定）**を追加予定
  （真剣な利用者だけを集めるための設計。現時点で画面はありません）。
- **ポイント・コインのような仮想通貨の概念は実装しません**（禁止事項。§4参照）。
  課金訴求も「誠実な月額プラン」の見せ方になります。

### 1.4 想定ユーザー像（デザインの前提）

- 45〜65歳。スマホ操作に不慣れな方も多い。老眼を考慮し、**文字は大きく・コントラストは十分に**。
- 婚活・再婚活動に対する不安（詐欺・遊び目的・年齢への引け目）を持っている。
  → 安心材料（本人確認バッジ、運営の見守り、通報機能）が視覚的に伝わることが重要。
- スワイプ操作は採用していません（一覧はグリッド表示）。迷わない・押し間違えないUIが最優先。

## 2. デザインの現状と課題

### 2.1 現状

現在のUIはエンジニアが実装用に**仮置き**したものです。配色・サイズの方向性
（白基調＋落ち着いた赤系）はオーナーの意向に沿っていますが、**プロのデザイン監修は一切
入っていません**。今回の発注で「トーンの軸を保ったまま、プロ品質に引き上げる」ことを期待しています。

### 2.2 現行デザイントークン一覧（すべて仮置き・変更提案歓迎）

実装は `apps/mobile/src/constants/theme.ts` にあり、全画面がこの値を参照しています。
納品時はこの表と同じ形式で「新しい値」を頂ければ、そのまま実装に反映できます。

| primaryPressed | #96281B | ボタン押下時 |
| primarySoft | #F9EBE9 | 選択状態の背景・バナー背景 |
| background | #FFFFFF | 画面背景（白基調） |

**文字サイズ（fontSize）** ※単位pt

| トークン名 | 現在値 | 用途 |

| heading | 20 | 見出し |

**フォントファミリー**: 未定義（OS標準のまま）。日本語フォントの指定提案も歓迎します
（ただしライセンス費用が発生する場合は事前に相談してください）。

### 2.3 現状の課題（デザイナーに解決してほしいこと）

1. **トークン体系が貧弱**: グレースケールの段階が少ない、警告色（warning）等のセマンティック
   カラーが不足、文字サイズの階層が浅い。体系立った再設計をお願いしたい。
2. **タブバーのアイコンが絵文字（🔍💌💬👤）の仮実装**。ちゃんとしたアイコンが必要。
3. **アプリアイコン・スプラッシュ画面・ロゴタイプが未デザイン**（現状は「ハピマリ」のテキストのみ）。
4. **状態デザインの不足**: 空状態（いいねが0件等）・エラー・読み込み中の見せ方が素朴。
5. 全体に「エンジニアが部品を並べただけ」の画面構成。情報の強弱・余白のリズム・
   世代に合った品位のあるビジュアルへの引き上げを期待しています。

### 2.4 変えてはいけない既存のデザイン原則（オーナー決定事項）

1. 一覧カードの表示は**「写真・名前・年齢・相性%」のみ**。結婚歴・子どもの有無・居住地は
   カードに出さない（詳細画面でのみ伝える）。
2. **相性%は85%以上のときだけ表示**する（特別感の演出。85%未満は非表示）。
3. **文字を写真の上に重ねない**。文字は大きく、写真の視認性を優先。
4. 子どもの有無を前面に出さない方針（2026-07-07オーナー決定。詳細画面での扱いは
   今後さらに縮小される可能性があります）。

## 4. 変更できないUI制約（開発仕様 SPEC §2・遵守必須）

以下は仕様として固定されており、デザインでも変更できません。

1. **最小フォントサイズ 16pt**（それ未満の文字を1箇所も作らない）
2. **主要ボタンの高さ 48pt以上**、**タップ領域 44pt以上**
3. **タブは4つ固定**: さがす / お相手から / メッセージ / マイページ（追加・削除・改名不可）
4. **1画面につき主要アクションは1つ**（迷わせない）
5. **派手な装飾の禁止**: ギラついたグラデーション・過剰なアニメーション不可
6. **UIテキストは全て日本語**（英語混じりの見出し等は不可）
7. **ポイント・コイン等の仮想通貨表現の禁止**
8. 破壊的操作（ブロック・退会等）には必ず確認ダイアログ
9. 白基調＋落ち着いた暖色系という大枠のトーン（具体的な色値の再提案は歓迎）
10. §2.4の既存デザイン原則（カード表示項目・相性85%ルール・文字を写真に重ねない）

## 5. 納品物の指定

| # | 納品物 | 要件 |
|---|---|---|
| 1 | **Figmaファイル** | 対象画面のデザイン。**コンポーネント化必須**（同じボタンが画面ごとにバラバラの部品にならないこと）。バリアント（押下・無効・選択状態）も定義 |
| 2 | **デザイントークン定義書** | §2.2の表と同じ形式で、色・文字サイズ・余白・角丸・部品サイズの数値表。**エンジニアがそのまま theme.ts に転記できること**が条件。Figma Variables での定義も歓迎 |
| 3 | **主要コンポーネント一式** | 下記の8種を最低限含む |

**主要コンポーネント（最低限）**

1. ボタン3種（プライマリ／セカンダリ＝枠線／危険系アウトライン）＋押下・無効・読込中状態
2. テキスト入力欄（ラベル・必須表示・補足文・エラー表示込み）
3. 選択肢ボタン（単一選択・複数選択・はい/いいえ。ドロップダウンは中高年向けに使わない方針）
4. お相手カード（グリッド用。写真/名前/年齢/相性%のみ）
5. チャット吹き出し（自分・相手・運営システムメッセージの3種＋時刻表示）
6. バナー（デート誘導・詐欺注意・審査状態などのお知らせ帯）
7. タブバー（アイコン4つ込み。現絵文字の置き換え）
8. 価値観タグのチップ（未選択・選択・「お相手と一致」の3状態）

## 7. デザインの方向性とNG例

### 7.1 目指す方向

- **可読性が最優先**。大きな文字・十分な行間・迷いのない導線。
- **落ち着き・安心感・誠実さ**。50代が使っていて恥ずかしくない、品位のある佇まい。
- 「誠実なサービスが、そっと背中を押してくれる」温かさ。事務的・病院的になりすぎない。
- 参考になる系統: 大人向けの上質なサービス（ホテル・百貨店・信頼系金融）の持つ静かな品格。

### 7.2 NG（避けてほしいもの）

- **若年向けのポップさ**: 明るいパステル大量使い・丸文字・絵文字多用・スタンプ的装飾
- **ギラつき**: ネオン・強いグラデーション・黒背景に金文字のような煽り系
- **診断テスト風・ゲーム風**の演出（心理テスト・ルーレット・ガチャ的な見せ方）
- ポイント・コイン等の**仮想通貨的な表現**（仕様で禁止）
- 「バツイチ」「子持ち」を強調するビジュアル（§1.2のポジショニングに反する）
- 文字の写真への重ね置き、16pt未満の文字（仕様で禁止）

## 8. スケジュール前提

- 開発は現在、機能実装の最終段階（残り: 通話機能=M5、課金・仕上げ=M6）です。
- **デザインの実装反映は M6（機能フリーズ）後**に行います。
  **デザイン作業自体は今から並行して進めて構いません。**
- M6では「中高年向けトーン統一」として**画面内の文言が見直される予定**です。
  文言が多少変わってもレイアウトが崩れない、文字数に寛容な設計をお願いします。
- 質問・相談はオーナー（中村）まで。技術的な実現可否は開発側（AIエージェント＋
  レビュー担当エンジニア）が回答します。

## 付録A: 技術環境（参考）

- アプリ: Expo (React Native)。iOS / Android 両対応。ダークモード対応は現時点で予定なし。
- デザイントークンは `apps/mobile/src/constants/theme.ts` の1ファイルに集約されており、
  数値の差し替えで全画面に反映される構造です。
- 既存コンポーネント実装: `apps/mobile/src/components/ui/`
  （AppButton / AppTextField / ChoiceGroup / ValueTagsSelector / Screen / PrefectureField）
  および `components/profile-card.tsx`。
