## 追加確認（設計書 §8.3）

### R4（いいね表示繰越・上限100）
- 上限100・複数日累積繰越・翌日解禁・男性無制限・境界（101件目）は **Vitest 8件で担保**（`like_visibility.test.ts`）。
- E2Eでの100件連投は非現実的のため設計書の指示どおり単体テストで代替。繰越文言（「ほかに n 件…明日以降に表示されます」）は実装済み。
- likesタブのRealtime: ゆみこがlikesタブを開いた状態で てつや からいいね送信 → **リロードなしで出現** ✅

### R10（検索の既定=自県+隣接県）
- seed全員が東京/埼玉/千葉（相互隣接）のため、ゆみこを一時的に**大阪府**に変更して検証:
  - 既定フィルタ（しんじ=東京都）: ゆみこ**非表示** ✅
  - フィルタモーダルで「全国」適用: ゆみこ**表示** + ボタンが「絞り込み中(1)」バッジ ✅
  - 検証後に千葉県へ復元済み。年齢→birth_date変換等はVitest 11件で担保（`discover_filters.test.ts`）。

### ブロック（blocks・両方向遮断）
- しんじがゆみこを詳細画面の「…」→ブロック（確認ダイアログ経由）→
  - しんじのdiscoverからゆみこが消える ✅ / 詳細は「表示できません」 ✅
  - REST実測: **両方向**で相手のprofilesが0件（RLS `is_blocked_between`）✅
- マイページ→「ブロックしたユーザー」→ 解除 → blocks 0件・discover再表示 ✅
  （※ブロック中は相手プロフィールがRLSで取得できないため、一覧は日時のみ表示。QUESTIONS.md Q9参照）

### 管理画面（§6）
- `/reports`: open通報の一覧（通報者・対象・理由・詳細）。同一ユーザーへ3件以上で**赤枠+⚠件数表示** ✅。
  Server Action「対応済みにする」→履歴へ移動 ✅ / 「棄却」✅ / 「対応済み+凍結」はUI配置確認（凍結自体は/usersで実測）
- `/users`: ニックネーム部分一致検索（`?q=はなこ`）✅ → 「凍結」（確認ダイアログ付き）→ 凍結中表示 ✅ →
  REST実測: 凍結中ユーザーは他ユーザーから**取得0件**（RLS）✅ → 「凍結解除」→ active復帰 ✅
- `/flagged`: 「いい投資の話があります」が 日時/送信者(ひろし)/受信者(みほ)/本文/**検知語「投資」** 付きで表示 ✅
- ダッシュボード: 「flaggedメッセージ 1件」カード追加・強調表示 ✅
