## 1. 目的

M5のモック通話（発着信の合図だけ動き、音声が流れない）に、Agora経由の実音声を通す。
**発着信・応答・拒否・切断・15分タイマー・通話ログはすべて実装済み**のため、
本スプリントで作るのは「入場券（トークン）を発行するサーバー」と「音声エンジンの接続」の2点。

## 3. サーバー側: `agora-token`（入場券の発行）

- 入力 `{ matchId }` → 出力 `{ ok, appId, channel, uid, token, expiresAt }`
- **JWT必須**。発行前の資格チェック（すべて満たさないと発行しない）:
  1. ログイン済み・`status = 'active'`
  2. そのマッチの**当事者**である（matches の user_a / user_b）
  3. マッチが**ブロックされていない**（既存 `is_match_blocked` を利用）
  4. （§6-1がAの場合）**両者とも本人確認済み**
  ※ 課金状態は**見ない**（2026-08-19 オーナー決定）
- トークン仕様: チャネル名 = matchId ／ uid = 自分のユーザーID ／
  **有効期限 = 16分**（15分上限＋接続猶予1分）。期限が切れるとAgoraが切断するため、
  **15分制限がクライアント改造では破れない**（サーバー側バックストップ）
- シークレットは Edge Function にのみ設定（`AGORA_APP_CERTIFICATE`）。アプリには一切埋め込まない。
  App ID もこの関数の応答で渡すため、アプリ側の環境変数は増やさない
- トークン生成は Agora 公式の `agora-token`（npm）を利用（Deno の node 互換で動作確認。
  不可の場合のみ生成ロジックを移植する）

## 4. アプリ側: `call-provider-agora.ts`（Web）

- 既存インターフェース `CallProvider`（startCall / joinCall / listen）をそのまま実装。
  **発着信の合図は現行の Realtime broadcast を流用**し、`connected` になる区間だけ
  Agora チャネルに join して音声を流す（=モックとの差分は「音が出る」ことだけ）
- 接続の流れ: 発信側は `agora-token` を取得してから invite → 相手が accept →
  双方 join → 通話。応答側も自分のトークンを取得して join（トークンは本人ごとに発行）
- マイク許可が拒否された場合は通話を `error` で終了し、
  「マイクの使用を許可してください」を表示（16pt以上・既存のエラー表示様式）
- Agora の SDK 読み込みは**通話画面でのみ動的 import**（初期バンドルを重くしない）
- ネイティブ（iOS/Android）は当面モックのまま（§6-2）。`Platform.OS === 'web'` で切替

## 5. 事故・リスクの洗い出しと対策

| # | リスク | 対策 |
|---|---|---|
| 1 | トークン無しで通話チャネルに入られる | Agora プロジェクトを「App ID + Token（Secured mode）」で作成（App Certificate 有効）。**トークン必須になり、発行はサーバーの資格チェックを通った人だけ** |
| 2 | トークンの漏えい・使い回し | 有効期限16分・チャネル（=マッチ）限定・本人uid限定。期限後は再発行が必要で、再発行時に資格を再チェック |
| 3 | 15分制限の迂回（クライアント改造） | トークン期限16分で**サーバー側から強制切断**（クライアントのタイマーは主にUX用） |
| 4 | ブロック直後の通話 | 発行時にブロックを検査。**通話中のブロックは即時切断されない**（既知の制限として許容。手動切断は常に可能。次善策はM8.1以降） |
| 5 | 未認可のマッチで発行させる | matches の当事者検査（サーバー）。RLSと同じ判定関数を利用 |
| 6 | 料金の暴走 | 音声のみ・毎月10,000分の無料枠。Agoraコンソールで使用量アラートを設定（オーナー作業・任意） |
| 7 | シークレットの置き場所ミス | `.env`（Git管理外）と Supabase Secrets のみ。デスクトップ（OneDrive）やメモアプリに保存しない |
| 8 | マイク許可拒否・非対応ブラウザ | エラー表示と再試行導線。HTTPSが必須（本番はドメイン取得後に自然に満たす。ローカルは localhost で可） |

## 6. 判断が分かれる点（A/B・推奨）

### 6-1. 通話に本人確認（is_verified）を必須にするか

| 案 | 内容 |
|---|---|
| A | **両者とも本人確認済みのときだけ通話可**（トークン発行で拒否＋通話ボタン非表示） |
| B | 現状どおり不要（マッチしていれば誰でも） |
| **推奨: A** | ウェルカム画面の約束「本人確認をしてから、やりとりがはじまります」と一貫。メッセージ送信は既に本人確認必須であり、**声のやりとりだけ本人確認なしで可能**という穴を塞ぐ。なりすまし・勧誘対策 |

### 6-2. ネイティブアプリ（iOS/Android）の対応時期

| 案 | 内容 |
|---|---|
| A | **Web先行**。本スプリントはWebのみ実音声、ネイティブは後続スプリント（`react-native-agora` + Expoの開発ビルドが必要） |
| B | 同時対応（工数増・ストア配信自体がまだ先） |
| **推奨: A** | 公開はWeb先行の方針。ネイティブ通話はストア配信の準備と同時にやるのが効率的 |

## 7. 動作確認方法（オーナーが自分でできる手順）

1. `supabase/functions/.env` に Agora の2値を設定（手順は §8）
2. `pnpm exec supabase start` → `pnpm exec supabase functions serve --env-file supabase/functions/.env`
3. `pnpm -F mobile exec expo start --web --port 8081`
4. **通常ウィンドウとシークレットウィンドウ**で1つずつブラウザを開き、
   マッチ済みのシードユーザー2人（例: けんじ seed02 ／ さちこ seed14・password123）でログイン
5. 片方のトーク画面から通話ボタン → もう片方に着信 → 応答 → **声が聞こえること**
   （同じPCなのでハウリング防止にイヤホン推奨）
6. 切断 → callsログに記録されること（マイページ等には出ない。DBのみ）
7. 15分制限は検証用に短縮できるようにする（環境変数 `AGORA_TOKEN_TTL_SECONDS` を
   ローカルのみ120秒等に設定 → 2分で自動切断されること）

受け入れ条件: ①マッチ当事者同士で発着信・通話・切断ができ音声が双方向に流れる
②非当事者・ブロック済み・（Aなら）本人確認未完了ではトークンが発行されない
③トークン期限で自動切断される ④マイク拒否でエラー表示 ⑤既存テスト・lint・型チェック全緑
⑥通話ログが従来どおり記録される

## 8. オーナー作業: Agoraアカウントの作成（所要5〜10分・無料）

> アカウント作成とパスワード設定は**ご本人の操作**が必要です（AIは代行しません）。

1. https://console.agora.io を開き **Sign up**（メールアドレス＋パスワード）
   - メールは**事業用**を推奨。勤務先の @meetsmore.com は使わないこと
2. ログイン後、左メニュー **Project Management** → **Create a Project**
   - Project name: `hapimari`
   - Authentication mode: **「Secured mode: App ID + Token」を選ぶ**（重要。§5-1の前提）
3. 作成したプロジェクトの **App ID** をコピー
4. 同じ画面で **App Certificate（Primary）を有効化**し、値をコピー
5. クレジットカード登録は無料枠（月10,000分）を超えるまで不要
6. **App ID と App Certificate の2つをこの会話で共有**（ローカルの `.env`＝Git管理外へ設定します）。
   デスクトップ（OneDrive同期）のメモ等には保存しないこと
