# I35 本番で HTTPS と確認できない要求を管理画面で拒否 設計提案（2026-09-26）

> 状態: **夜間指示書 §1 により推奨案で自己承認して実装**。方針: 2026-09-24 決定 I35＝A「本番では HTTPS と確認できない要求を拒否（ヘッダ欠落も拒否）。実際のプロキシ構成を確認してから入れる」。根拠: 統合表 I35（Grok#12）。
> 作成: Claude Opus 5.5（夜間自律作業・モードA）。人間レビューの段階: (C) 本番公開前（本番構成に依存するため）。

## 1. 目的

`apps/admin/middleware.ts` は本番で `x-forwarded-proto` が `https` 以外なら 403 を返すが、**ヘッダが無いときは素通し**していた（`proto !== null &&`）。Basic 認証のパスワードを平文で流させない防御として、HTTPS と確認できない要求はすべて拒否する。

## 2. 前提（プロキシ構成の確認・2026-09-26）

本番アプリは未デプロイのため、実環境のヘッダは確認できない。Vercel（管理画面の配信予定先）の公式ドキュメントで次を確認し、これを前提とする。

| 確認した事実 | 出典 |
|---|---|
| 「The CDN automatically forwards any HTTP requests to your deployment to HTTPS using the `308` status code」「HTTPS redirection is an industry standard and can't be disabled」 | https://vercel.com/docs/cdn-security/encryption |
| `x-forwarded-proto`: 「This header represents the protocol of the forwarded server, typically `https` in production and `http` in development」 | https://vercel.com/docs/headers/request-headers |

→ Vercel 上では、関数（middleware）に届く要求は HTTPS で、`x-forwarded-proto: https` が付く。ヘッダの欠落は正規の経路では起きないので、欠落も拒否して安全側に倒す。

## 3. 設計方針

- 判定を純粋関数 `isUnverifiedHttpsInProduction(proto, NODE_ENV)` として `apps/admin/lib/basic-auth.ts`（I18 で新設）に置き、middleware はそれを呼ぶ。
- 本番（`NODE_ENV=production`）でだけ判定。`https`（大文字小文字は区別しない）なら通す。複数値（`a, b`）は先頭で判定。欠落・空・`http`・不明な値は 403。
- 本番以外（`next dev`）は従来どおり判定しない。

### 判断が分かれる点

| # | 論点 | A（推奨・採用） | B | 理由 |
|---|---|---|---|---|
| 1 | ヘッダ欠落 | 拒否 | 許可（旧挙動） | 決定どおり。Vercel では欠落しない前提を公式文書で確認済み |
| 2 | Server Action 側（`assertAdminAuth`）にも入れるか | 入れない | 入れる | middleware が全リクエスト（matcher で静的ファイル以外すべて）を先に通すため。決定の範囲は middleware |

## 4. リスクレベル: **高**（本番設定・管理画面の認証）

## 5. リスク・副作用

- **Vercel 以外の配信先に移す場合、またはヘッダを付けないプロキシを前段に置く場合、管理画面が全面 403 になる**（fail-closed）。移設時はこの判定を見直すこと。
- ローカルで `next start`（本番モード）を直接開くと、ヘッダが無いので 403 になる（確認時は `x-forwarded-proto: https` を付ける）。

## 6. 動作確認方法

- Vitest で判定関数（https/HTTPS/複数値/http/欠落/空/本番以外）。
- ローカルの本番ビルド（`next build`→`next start`）で、欠落 403・http 403・https＋正しい認証 200・https＋誤り 401。
- 本番デプロイ後: 管理画面が通常どおり開けること（開けなければ前提が崩れている）。

## 7. 確認質問

なし（方針 A で確定済み）。本番初回デプロイ時に、管理画面が開けることの確認だけお願いしたい。
