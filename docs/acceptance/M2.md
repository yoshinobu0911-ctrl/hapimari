# M2: 本人確認フロー（モック）+ 管理画面審査 — 受け入れ記録

実施日: 2026-07-06 / 実施者: Claude Code（AIエージェント）
検証方法: モバイル（Expo Web）と管理画面（Next.js）を同時起動し、ブラウザ実操作でE2E実行

## 受け入れ条件（SPEC §6 M2）

> admin承認で即座にアプリ側バッジ表示が変わる（Realtime）。

## 結果: ✅ 合格

### 1. 承認 → Realtimeバッジ反映（E2E・最重要）

| ステップ | 結果 |
|---|---|
| ユーザー（はなこ改・未認証）が本人確認書類を提出 | verifications に pending 行作成、書類は非公開バケットへ ✅ |
| アプリの提出画面 | 本人確認=「審査中」/ 収入・独身=「未提出」と表示 ✅ |
| アプリのマイページを**開いたまま**にする | 「本人確認 未提出」表示 |
| 管理画面 /verifications | 審査キューに申請が表示（申請者名・種別・**署名URLで書類画像プレビュー**）✅ |
| 「承認する」をクリック | review_verification 関数で status=approved + is_verified=true を原子的に更新 ✅ |
| **開いたままのマイページ** | **リロードなしで約1秒後に「✓ 本人確認済み」に変化** ✅ |
| 管理画面 | キューが空になり、審査履歴に「はなこ改 / 本人確認 / 承認」が記録 ✅ |

DB実測: `profiles.is_verified=true` / `verifications.status='approved', reviewed_at 記録済み`

### 2. R2: 未認証ユーザーのメッセージ送信ブロック（RLS）

| ケース | 結果 |
|---|---|
| is_verified=false のユーザーが messages に INSERT | **403** `new row violates row-level security policy` ✅ |
| is_verified=true に戻して同じ INSERT | 201 Created ✅ |

（テストデータは削除し、matches.message_count も元に戻した）

### 3. 書類の秘匿性

- 書類バケット（verifications）は**非公開**。匿名の公開URLアクセスは拒否（400）✅
- 本人は他人の申請行を閲覧不可（RLS: user_id = auth.uid() のSELECTのみ）
- 管理画面は service_role の**署名URL（1時間有効）**で書類を閲覧

- migration `20260706100000_m2_verification.sql`:

## 手動確認手順（人間向け）

1. cowork directory の **「ハピマリを起動.bat」**（アプリ）と **「管理画面を起動.bat」**（運営画面）をそれぞれダブルクリック
2. アプリ側: マイページ →「証明書類を提出する」→ 画像を選んで提出 →「審査中」になる
3. 管理画面: 「本人確認審査」→ 書類画像を確認して「承認する」
4. アプリ側: マイページのバッジが（リロードせずに）「✓ 本人確認済み」に変わる
