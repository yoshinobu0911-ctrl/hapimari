## 0. リリースとは何をすることか

いまアプリは**中村さんのPCの中だけ**で動いています。公開するとは、次の2つをインターネット上に置くことです。

| # | 何を | どこに | 現状 |
|---|---|---|---|
| A | **データベースなどの裏側**（会員情報・写真・決済処理） | Supabase の本番プロジェクト | ローカル（Docker）のみ |
| B | **画面**（利用者がブラウザで見る部分） | ホスティング（Vercel等） | ローカルのみ |

この2つを用意して、取得済みのドメインをBに向ける。これが「リリース」です。

## 1. 手順（上から順に）

### STEP 1: Supabase 本番プロジェクトを作る 〔中村さん〕

1. supabase.com でプロジェクトを新規作成
2. **リージョンは Tokyo (ap-northeast-1)** を選ぶ（利用者が日本のため）
3. プラン: 無料枠でも動くが、**Pro（$25/月）を推奨**
   - 理由: 無料枠は一定期間アクセスが無いと**自動停止**する。また日次バックアップが付く
4. 発行される **URL** と **anon key** を控える（サービスロールキーは絶対に共有しない）

### STEP 2: 裏側を本番へ流し込む 〔エージェント実行可〕

```bash
supabase link --project-ref <プロジェクトID>
supabase db push                 # migration 21本を適用
supabase functions deploy like stripe-checkout stripe-webhook stripe-cancel
```

**シークレットの設定**（値は中村さんが用意・Gitには入れない）:

```bash
supabase secrets set STRIPE_SECRET_KEY=... STRIPE_WEBHOOK_SECRET=... \
  STRIPE_PRICE_MALE_1M=... STRIPE_PRICE_MALE_3M=... STRIPE_PRICE_MALE_6M=... \
  APP_BASE_URL=https://<取得したドメイン>
```

> ⚠️ **シードデータ（テスト用の20人）は本番に入れない。** 本番は会員ゼロから始めます。

### STEP 3: 画面をビルドしてホスティングに載せる 〔エージェント実行可〕

```bash
cd apps/mobile
npx expo export -p web          # dist/ に静的ファイルが出る
```

ホスティングは **Vercel を推奨**（無料枠あり・独自ドメイン対応・設定が最も少ない）。

- Vercelのアカウント作成とGitHub連携は 〔中村さん〕
- プロジェクト設定（ビルドコマンド・出力先・環境変数）は 〔エージェント〕
- 環境変数に **Supabaseの本番URLとanon key** を設定する

### STEP 4: ドメインをつなぐ 〔中村さん＋エージェント〕

1. Vercel に取得済みドメインを追加
2. 表示されるDNSレコードを、ドメイン管理画面（Xserver等）に登録 〔中村さん〕
3. 反映まで数分〜数時間。**httpsは自動で付く**（証明書の手配は不要）

### STEP 5: Stripe を本番に切り替える 〔中村さん＋エージェント〕

1. Stripe本番アカウントの審査通過を確認 〔中村さん〕
2. 本番の商品・価格を3つ登録（4,980 / 11,940 / 16,680円） 〔中村さん or エージェント〕
3. Webhookエンドポイントを登録: `https://<プロジェクトID>.supabase.co/functions/v1/stripe-webhook`
4. 本番キーを STEP 2 の方法で差し替え

### STEP 6: 法定表示を載せる 〔中村さん〕

`docs/legal/` の3書面の `{{ }}` を埋めて公開する。

- 事業者名・代表者名・所在地・電話番号・問い合わせメール
- **届出受理番号**（出会い系サイト規制法の届出後に交付）

### STEP 7: 公開前の最終確認 〔エージェント〕

本番URLで実際に通して確認する。

- [ ] 新規登録 → 本人確認の提出 → 管理画面で承認 → 検索 → いいね → マッチ → メッセージ
- [ ] 決済（本番カードで1件だけ実行し、**返金する**）
- [ ] 解約 → 期間末まで使えること
- [ ] 管理画面にBasic認証がかかっていること
- [ ] 法定表示3ページが表示されること

## 6. 段階的に公開する案（推奨）

いきなり全開でなく、2段階に分けるとリスクが小さくなります。

| 段階 | 内容 | 必要な前提 |
|---|---|---|
| **第1段階: 招待制の無料公開** | 知人・モニターに限定公開。課金なし | 届出のみ（**Stripe不要**） |
| **第2段階: 一般公開＋課金開始** | 広告を回して集客 | 上記＋Stripe＋決済画面 |

第1段階なら**届出さえ通れば公開できます**。実利用者の反応を見てから課金を載せられるため、
初期の作り込みが無駄になりにくく、決済トラブルのリスクもゼロから始められます。

**注意**: 無料でも「インターネット異性紹介事業」に該当するため、**届出は第1段階でも必須**です。
