## 受け入れ条件（SPEC §6 M5）

1. 通話解禁前は通話ボタン非表示
2. 解禁後に発着信できる
3. 15分で自動切断
4. callsログ記録

### 3. 15分自動切断

- 実装: 残り秒数が0で自動 hangup（`remainingCallSeconds`・`CALL_MAX_DURATION_SECONDS=900`）。
- 検証: **Vitest 8件で900秒境界を担保**（899秒=残り1/900秒=残り0/負値なし/時計逆行）。
  実時間15分のE2Eは行わない（設計承認済み判断#3。M4の「翌日」判定と同じ方式）。
- 画面には「残り mm:ss（最長15分で自動終了します）」を常時表示。

### 4. callsログ（DB実測）

```
match_id: 10000000-…-0001 / started_at: 06:38:53 / ended_at: 06:39:22 / duration_seconds: 29
```
応答時に発信者がINSERT・終了時にUPDATE（二重書き込み防止のため発信者のみが書く規約）✅

## 実装中に発見・修正した不具合（重要・Q15）

**同名Realtimeチャネルの leave/join 競合**: チャットの着信リスナーと通話セッションが同じチャネル名
`call-{matchId}` を使うため、画面遷移時に「リスナーの離脱」と「通話の参加」が競合し、
通話チャネルが購読できず「接続しています…」のまま止まる不具合をE2Eで発見。
→ **リスナーの停止を `await` してから通話画面へ遷移する**修正で解決（`CallListener.stop` を
Promise化）。再E2Eで両方向とも成立を確認済み。

## 既知の制限（委託エンジニア向け）

1. **音声は流れない**（モック。画面に明示済み）。Agora契約後に `CallProvider` の別実装で差し替え。
2. **着信はチャット画面表示中のみ**（承認済み判断#4。画面にも明示）。本番はプッシュ通知で解消。
3. broadcastチャネルはRLS対象外（設計書§8-3の許容リスク）。イベントのfrom検査で当事者外を無視。
   Agora本実装ではトークン認証に置き換わる。
4. 通話ログは発信者クライアントが書くため、発信者側が通話中に落ちると ended_at が欠損しうる（MVP許容）。

## 手動確認手順（人間向け）

1. ブラウザ2枚（例: `localhost:8081` と `127.0.0.1:8081`）で seed01 / seed13 にログイン
2. 両方で「たかし×ようこ」のチャットを開く → 片方で📞 → 注意ダイアログ→OK → もう片方に着信バナー → 応答
3. 双方が「通話中」+タイマー表示になれば成功（音声は流れません）
