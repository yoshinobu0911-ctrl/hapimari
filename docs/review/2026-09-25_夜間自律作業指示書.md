## 3. 夜間の絶対禁止（例外なし・迷ったらやらない）

- `git push`／origin への操作。コミットはローカルにだけ積む（翌朝オーナーが push を判断）。
- 本番への一切の反映: `supabase db push`／`functions deploy`／`secrets set`／Vercel 操作／DNS。
- `.env` 系ファイルの編集、APIキー・シークレットの記載、`secure/` 配下の読み書き。
- 依存パッケージの追加、グローバルツールのインストール（Deno を含む。無くて検証できない項目は「未検証」と記録する）。
- 憲法 §7 の禁止事項（RLS・認証・バリデーションの迂回、失敗テストの無効化、未完了の「できました」）。
- ローカル DB 以外のデータ削除・上書き。ローカル DB の `db reset` と一時変更は Q2＝A の範囲で可。**変更後は必ず元に戻し、SQL テスト全スイートを再実行して戻ったことを確認する**。
- 設計提案に書かれていない判断が必要になった項目を、推測で進めること。→ その項目を中断し、状態を記録して次の項目へ。
- 他セッションが作ったファイルへの変更・コミット混入。
- オーナーにしか決められない事項（法務・費用・本番URL・届出・レビュアー宛の投稿）に踏み込むこと。→ 翌朝確認事項へ。

## 4. 各項目の共通手順（Definition of Done）

1. **設計提案**（P2 の6件は作成済みなので不要。他は `docs/design/2026-09-26_<ID>_設計提案.md` に憲法 §4 の7項目で書く。モードAではその末尾に「夜間指示書 §1 により推奨案で自己承認して実装」と1行書く）
2. **実装**: 承認された範囲だけ。migration は新規ファイルのみ。
3. **検証**: §0-4 の4種をすべて流す。追加したテストは「意図的に壊すと赤になる」ことを1回確かめる（恒真テスト防止）。
4. **受け入れ記録**: `docs/acceptance/2026-09-26_<ID>.md` に「対象・確認方法・前提・未検証の項目・翌朝オーナーに見てほしい点」を書く。
5. **統合表**: [統合指摘表](2026-09-24_統合指摘表.md) の該当行の状態欄を「済（コミット短縮ハッシュ）」に更新する。
6. **コミット**: 1項目1コミット。日本語メッセージ。自分のファイルだけをパス指定で add。末尾に `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`（降格時は実際のモデル名）。
7. **progress.md 更新**: 「✅ 完了したこと」に1行追加、「🚧 進行中」を次の項目に書き換える（コンテキスト圧縮や中断に備える）。
8. **失敗したとき**: 同じ原因で2回失敗したら、自分が変更したファイルだけ `git restore` で戻し、原因・試したことを報告書に記録して次の項目へ。テストの削除・条件緩和で「通す」ことは禁止。

## 5. 終了処理（キューを消化した／これ以上進めない、のどちらでも必ず実行）

1. `git status` が `.agents/` 以外クリーンであることを確認（自分の未コミット変更を残さない）。
2. **夜間作業報告** `docs/review/2026-09-26_夜間作業報告.md` を作成。非エンジニア向け・結論ファースト・表形式:
   - 結果サマリ（済／設計提案のみ／中断／未着手 の件数と ID）
   - コミット一覧（ハッシュ・1行要約・触った領域・憲法 §6 該当か）
   - 検証結果（各コマンドの最終結果。未検証は「未検証」と書く）
   - **翌朝のオーナー確認事項**（判断が要るものだけ。最大10件、優先度順、A/B/C＋推奨つき）
   - push の可否についての推奨（「全部 push 可」「このコミットだけ確認後に」など）
   - 追加の発見（依頼外で見つかった不具合。直していないもの）
3. `tasks.md` を実態に合わせて更新（済んだものを消し、新しい判断待ちを追加）。
4. `progress.md` の「🎯 現在のゴール」と「🚧 進行中」を更新し、「🚧 進行中」は「（なし）」または再開に必要な1行にする。
5. 最後のチャット出力で、報告書のパスと「翌朝の確認事項」の上位3件だけを表示して終える。

## 6. 停止条件

- キューを消化した → §5 へ。
- モデルの使用上限・環境障害で作業不能 → 直ちに §5 へ（途中の項目は「中断」として状態を記録）。
- 許可プロンプトで止まった場合はオーナーの応答を待つ（自動承認モードで想定外の操作を要求したということなので、無理に別手段で回避しない）。
