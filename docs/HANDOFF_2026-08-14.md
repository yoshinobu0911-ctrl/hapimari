## 7. 作業上の注意（前スレッドで得た教訓）

- SupabaseはSQLからストレージのファイルを直接削除できない（Storage API経由のみ）→ 削除待ちキュー方式で実装済み。
- `nslookup` でのドメイン存在確認は当てにならない（サーバー応答を誤検知）。**JPRS Whois で確認すること**。
- マイグレーションは**再実行できる形**（`if not exists` / `drop ... if exists`）で書く。
- Pythonでファイルを書き換えると改行コードがCRLFになりBiomeが落ちる → 書き換え後は `biome format --write` を流す。
- 「対策済み」と書いた設計を鵜呑みにしない。**M6.5で対策したはずの三点測位が、実は数学的に破れていた**（多点観測の検証をしていなかったため）。受け入れテストは「攻撃を実際に再現する」形で書くこと。
