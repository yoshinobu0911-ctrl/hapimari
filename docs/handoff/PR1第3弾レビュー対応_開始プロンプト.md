## 3. 守ること

- A・B は CLAUDE.md §6 のセンシティブ領域（決済・個人情報）で**リスク「高」**。オーナーの明示承認まで実装しない
- C（テストのみの変更）はリスク「中」扱い。提案を出して一度確認してから実装する
- 例外として G（nits 2件＝#25・#26）はリスク「低」・1〜2ファイルのドキュメント修正なので、提案と実装を1回でまとめてよい（変更内容は報告）
- 9/02 の反省（`docs/review/2026-09-02_指摘棚卸し.md` 冒頭）: 「対応済み」は必ず実測かコードの `file:line` を根拠にする。**#3 のとおり `scripts/run_sql_tests.sh` は ERROR を FAIL として数えないため、直すまでは緑を根拠にしない**
- 外部エンジニアの Issue が届いていて本件と重なるものがあれば、棚卸し表に Issue 番号を併記する
- コミットは論理単位・日本語。作業ブランチに push する
