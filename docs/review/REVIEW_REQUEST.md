## 5. 納品方法

### 5.1 指摘は GitHub Issue で（1指摘＝1 Issue）

タイトルの先頭に重要度を付けてください（PR #1 で使われている表記に合わせています）。

| 表記 | 意味 |
|---|---|
| `[must]` | 公開前に直さないと危ない（情報漏えい・なりすまし・課金の不整合・データ破損など） |
| `[suggestion]` | 直したほうがよい（将来の作り直し・性能劣化を防ぐ） |
| `[imo]` | 選択肢・好みの提示 |
| `[ask]` | 意図の確認 |

本文は次の4点があれば十分です（該当コードは GitHub の permalink を貼っていただければ OK です）。

```
## 何が問題か
## 放置すると起きること（具体例）
## 該当箇所（permalink）
## 直し方の方針（コードは不要です。方向性だけで大丈夫です）
```

### 5.2 最後に総評を1本

タイトル `[総評] 裏側の全体評価` で、次の内容をお願いします。

- 全体の評価（このまま育てて大丈夫か／どこが弱いか）
- 優先して直すべきもの トップ5
- AI に守らせるべきルールの提案（`CLAUDE.md` に反映します）
- 今後のレビューの進め方の提案（任意）

### 5.3 Issue にしたい理由

- こちらは Issue を1件ずつ AI に渡して直します（「#12 を直して」で作業を始められます）
- 修正 PR に `Closes #番号` を付けて紐づけるので、どの指摘がどこまで直ったかを GitHub 上で追えます
- 以前、PR の行コメントでいただいた指摘を見落としてしまったことがあり（`docs/review/2026-09-02_指摘棚卸し.md`）、その再発を防ぎたいです

コードの特定の行について書くほうがやりやすい箇所は、PR #1 へのコメントでも大丈夫です（その場合も `[must]` などを付けていただけると助かります）。

## 7. ローカルでの動かし方

前提: Node.js 20 以上 / pnpm / Docker

```bash
pnpm install
pnpm db:start   # Supabase ローカル起動
pnpm db:reset   # migration + seed の投入
pnpm dev        # アプリ（http://localhost:8081）と管理画面（http://localhost:3000）
```

- Supabase Studio: http://localhost:54323
- 環境変数: `apps/admin/.env.example`・`apps/mobile/.env.example`・`supabase/functions/.env.example` をそれぞれ `.env` にコピーして使います。管理画面は `ADMIN_PASSWORD` を設定するか、ローカル限定で `ADMIN_ALLOW_INSECURE=1` を設定しないと 503 になります
- 決済・通話の実際の動作には Stripe / Agora のキーが必要です（なくても、それ以外の機能は動きます）
- テストユーザー: `seed01〜20@hapimari.test` / `password123`（01〜12 が男性・13〜20 が女性。全員本人確認済み）
- テスト: `pnpm test`（Vitest）／ `bash scripts/run_sql_tests.sh`（SQL の攻撃再現テスト）
  - ※ `run_sql_tests.sh` は「途中で ERROR が出ても PASS と表示される」というご指摘を PR #1 でいただいていて、まだ直っていません。結果はログ全文で確認してください
- `CLAUDE.md` は AI 向けの開発ルールです。Windows 固有の注意（作業パス・PATH 補正など）はオーナーの環境向けなので、Mac / Linux では気にしなくて大丈夫です
