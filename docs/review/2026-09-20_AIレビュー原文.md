## [4055523941] scripts/run_sql_tests.sh

![must](https://img.shields.io/badge/review-must-red.svg)

アサーションが1件も走らなくても「全スイート PASS（FAIL 0件）」と出ます。

18行が数えているのは `FAIL` で始まる行だけで、psql の `ERROR:` も `docker exec` 自体の失敗も0件として通ります。4本のスイートはどれも全体が1トランザクション（例: `scripts/test_review2_fixes.sql:11` の `begin` から288行の `rollback`）なので、途中で1文でも ERROR になると以降は全部 `current transaction is aborted` で落ち、PASS/FAIL が1行も出ないまま24行の成功メッセージが出ます。

手元で grep の挙動だけ確かめました。

```
$ printf 'psql:/tmp/x.sql:11: ERROR:  current transaction is aborted\n' \
  | grep -cE "^[[:space:]]*FAIL|NOTICE:[[:space:]]+FAIL"
0
```

`docs/review/2026-09-02_指摘棚卸し.md` が30件の「対応済み」の根拠にこのスクリプトの緑を使っているので、ここが素通しだと棚卸し全体の確度が落ちます。psql の終了コードと `ERROR` 行数を `FAIL_TOTAL` に足すのと、スイートごとに期待する PASS 件数を突き合わせるのを入れたいです。
