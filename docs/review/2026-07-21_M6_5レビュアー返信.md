## boooleonardo（Leo）さんへ

ご指摘ありがとうございました。公開前に必須の6点を1スプリント（M6.5）でまとめて対応しました。

- **三点測位での自宅特定**: 距離RPCを「正確なkm」から**表示と同じ帯域＋ペア固定ジッター（±1.5km・ペアIDから決定的に算出）**に変更しました。何度測っても同じ値が返るので、繰り返し測定で誤差を平均化して消す攻撃が効きません。位置更新も30分に1回・1日8回までに制限しています。攻撃者役で位置を3回ずらして測距する再現テスト（scripts/test_m65_p1.sql の T9）で、真距離5.6km前後に対し取得値が全部「3km」に丸まり、交点を作れないことを確認しました。
- **写真バケットの公開・悪意あるURL**: バケットを非公開化し、`photo_urls` は URL ではなく**バケット内パス**を保持する形に移行しました。表示は毎回1時間有効の署名付きURLを発行します。外部URLを差し込む余地がなくなります。加えて**写真の事前審査キュー**を入れ、承認されるまで本人以外には表示されません（管理画面に「写真審査」ページを追加）。
- **birth_date の露出**: 他人のプロフィール取得を `profiles_public` ビューに一本化し、**誕生日そのものは返さず、サーバー側で計算した年齢（整数）だけ**を公開します。`profiles` 本体のSELECTは本人の行のみに制限しました。
- **ブロックが非表示だけ**: `is_match_blocked` ヘルパを作り、メッセージ送信・通話記録・デート相談をすべてDB層で拒否するようにしました。
- **いいねの一言メッセージにNGワード検査がない**: Edge Function で詐欺ワード辞書（チャットのflaggedと同じ）を通し、検知したら送信自体を拒否します（未マッチの相手に届くため、警告ではなく拒否にしています）。「投資で必ず儲かる」→拒否、通常文→送信成功をREST経由で確認済みです。
- **review_verification が reviewed_by 未記録**: 引数を追加して記録するようにしました。

「BEサーバーを一枚挟む」構造変更と課金の期間管理は、Stripe実装と同じ工事になるため M7 でまとめて対応します。

## satoman0703（さとまん）さんへ

的確なご指摘、助かりました。

- **管理画面が無認証で service_role**: Next.js の middleware で Basic認証をかけ、各 Server Action の冒頭でも同じ認証を再検証する二重構成にしました。`ADMIN_PASSWORD` 未設定の本番ビルドは管理画面を全遮断します（保護なしで公開されない）。本格的な管理者ログイン（Supabase Auth + 管理者テーブル）は、ご提案どおり M7 の BEサーバー導入と同時に作り込みます。
- **距離を返す相手の限定**: RPCが距離を返す対象を「active かつ 異性 かつ 非ブロック」に限定しました。ブロック相手の距離は取得できません。
- **env未設定でデモ鍵に静かにフォールバック**: mobile / admin とも本番（NODE_ENV=production / 非__DEV__）では環境変数を必須にし、無ければ起動時に明示エラーを出すようにしました。
- **モデレーションAPI**: 写真は当面「人力審査＋AI差し込み口」の構成にしています。AI画像解析は外部API（Rekognition / Vision SafeSearch 等）のキー取得が前提のため、キー設定後に有効化できるようインターフェースだけ先に用意しました（apps/admin/lib/photo-ai.ts）。

インデックス・enum化・レートリミット・CI RLSチェックは、MVP段階では許容とのことでしたので、スケール段階のバックログに積んでいます。
