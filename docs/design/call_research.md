# 音声通話の実装方式 調査書（VoIP vs 電話番号マスキング）

> 作成: 2026-08-19（オーナー依頼の調査。コード変更なし）
> 目的: マッチ後のユーザー同士が**電話番号を交換せずに**音声通話できる機能の方式選定
> 料金はすべて **2026-08-19 時点の各社公表値・1ドル=150円換算**。契約前に最新値の再確認が必要。
> 決定後の設計書は別途作成する（本書は比較資料）。

---

## 1. 現在のプロジェクト構成（調査結果）

| 層 | 使っているもの | 通話との関係 |
|---|---|---|
| 画面（フロント） | Expo（React Native）+ expo-router。**Web先行公開**・ネイティブは後続 | 通話画面 `call/[matchId].tsx`・着信UIは**実装済み**（音だけ出ないモック） |
| サーバー | Supabase Edge Functions（Deno）。Stripe決済で「JWT認証＋資格チェック＋シークレットはサーバーのみ」の型が確立済み | 通話の「入場券（トークン）発行」も同じ型で作れる |
| DB | Supabase Postgres + RLS。`calls` テーブル（通話ログ: 開始・終了・秒数）実装済み。INSERTは当事者かつ非ブロックのみ | 変更ほぼ不要 |
| 通話まわりの既存資産 | `packages/shared/call-provider.ts` = **差し替え用の共通インターフェース**（SPEC §8）。発着信・応答・拒否・切断・15分タイマー・30秒無応答タイムアウトのシグナリングは Supabase Realtime で**動作済み** | **「音声エンジンだけ」を差し込めば完成**する設計に最初からなっている |

重要な前提: SPEC・M5設計書・引き継ぎメモのいずれも「Agora等のVoIP SDKを契約後に差し替える」前提で作られている。

## 2. 2方式のしくみ（比喩で）

**(a) アプリ内VoIP通話** … LINE通話と同じ方式。
音声は**インターネット経由**で流れる。電話番号は一切使わない（知る必要も集める必要もない）。
アプリ（ブラウザ）を開いた状態で発着信する。例: Agora / SendBird Calls / Amazon Chime SDK。

**(b) 電話番号マスキング** … 宅配ドライバーからの電話と同じ方式。
実際の**電話回線**で話すが、間に「仮の050番号」を挟むので相手に本当の番号は見えない。
例: Twilio Voice（+ Proxy機能）。ただし**双方の本当の電話番号をサービス側が預かる**必要がある。

## 3. 比較表

| 観点 | (a) アプリ内VoIP | (b) 番号マスキング |
|---|---|---|
| 電話番号の扱い | **集めない・使わない** | **両者の実番号を収集・SMS認証・保管**（新たな機微情報） |
| 通話費用（15分1回・下記§4） | **約4.5円**（Agora/SendBird） | **約440〜830円**＋番号レンタル月額 |
| 月1万通話分の費用 | 約1,500円（無料枠超過分のみ） | 約29万円〜 |
| 既存コードとの相性 | ◎ 差し替えポイントに音声だけ差す | △ 番号収集・認証・番号プール管理を新規開発 |
| Web先行公開との相性 | ◎ ブラウザで通話できる（WebRTC） | ○ アプリ不要（普通の電話として成立） |
| 15分制限・通報・課金ゲート | ◎ アプリ内で完結（トークン期限で強制も可） | △ 通話がアプリの外に出るため制御が弱まる |
| 通話品質 | 回線品質に依存（国内はおおむね良好） | ◎ 電話網なので安定 |
| 中高年への優しさ | アプリを開く必要がある | ◎ 普通の着信として出られる／△ 知らない050からの着信は取られない・迷惑電話と誤解されるリスク |
| 事業者側の手続き | Agoraはサインアップのみ（営業契約不要） | 日本の番号取得に事業者確認書類（規制対応）が必要 |
| 成熟度 | Agora=大手マッチングアプリ採用実績あり | **Twilio Proxyは8年以上「Public Beta」のまま**（正式版の保証なし）。自作する場合は番号プール管理を自前実装 |

## 4. 費用の計算根拠（公表値・2026-08-19確認）

- Agora 音声: **$0.99/1,000分**（参加者ごと課金。1対1の15分=30分ぶん→$0.0297≒4.5円）。**毎月10,000分の無料枠**（=15分通話 約333回/月まで0円）
- SendBird Calls 音声(P2P): **$0.0010/分/人**（15分1対1≒4.5円）。前払いクレジット制
- Amazon Chime SDK: **$0.0017/分/人**（15分1対1≒7.7円）＋AWSアカウント運用が別途必要
- Twilio 日本向け: 携帯への発信 **$0.185/分**・着信 **$0.0100/分**・番号 **$4.75/月**（国内番号）
  - マスキング1通話（15分）: 両者へ発信方式=30分×$0.185≒**830円** ／ 片側着信方式≒**440円**＋発信者自身の通話料（かけ放題プーラン次第）
  - 同時に通話できる組数ぶんの番号レンタルが別途必要

## 5. 推奨: **(a) アプリ内VoIP、実装は Agora**

理由（順に重い）:

1. **費用が約100倍違う**。月1万通話分でも1,500円 vs 29万円。男性月額3,980円の粗利構造でマスキング型は成立しにくい
2. **既存コードが「Agora差し替え前提」で完成している**。発着信・15分タイマー・通話ログ・画面はすべて動作済みで、音声エンジンの差し込みだけで済む（最短距離）
3. **電話番号という新たな個人情報を集めずに済む**。退会時削除・RLS・漏えいリスクの管理対象を増やさない（本アプリの安全設計と一貫）
4. Web先行公開でそのまま動く（ブラウザ通話）。ネイティブ版は後続スプリントで対応（Expoの開発ビルドが必要になる点だけ注意）
5. 15分制限・通報・「本人確認済みのみ」等の安全ルールをアプリ内で強制し続けられる（トークン発行時にサーバーで資格チェック）

同カテゴリ内の比較: SendBirdは同価格帯だが通話は同社の付随製品でチャットが主力。ChimeはAWS運用の学習コストが増える。**実績・情報量・無料枠でAgoraが最有力**（引き継ぎメモの既定路線とも一致）。

マスキング型を選ぶ合理性があるのは「アプリを開かせること自体が難しい層に、電話として届けたい」場合のみ。費用と個人情報の重さから、本サービスでは採らない。

## 6. オーナーに確認したいこと（実装設計の前に・最大3つ）

1. **通話は男性の有料機能か**: 特商法ドラフトは有料機能として列挙しているが、現在のDB・画面は未課金男性も通話可能。本実装ではトークン発行時に課金チェックを入れるのが自然（メッセージと同じ扱い）。→ 入れる/入れないの確認
2. **録音を残すか**: 安全対策（通報時の証跡）として通話録音は可能（Agoraクラウド録音 $1.49/1,000分 目安・別料金）。プライバシーポリシー改訂が必要になるため、初期リリースでは「録音なし」を推奨。→ 方針確認
3. **Agoraアカウント作成を進めてよいか**: サインアップ無料・従量課金・営業契約不要。作成いただくのは「アカウント＋App ID＋App証明書」のみ（Stripeのときと同様、シークレットはEdge Functionにだけ設定）

## 7. 決定後の進め方（見通し）

設計提案 → 承認 → 実装（規模感 M）。内訳: ①Edge Function `agora-token`（資格チェック＋トークン発行）②`call-provider-agora.ts`（Web SDK・既存インターフェース準拠）③通話画面の接続（変更小）④callsログの厳密化。ネイティブ対応・録音は後続。
