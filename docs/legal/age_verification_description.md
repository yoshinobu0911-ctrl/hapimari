# 児童でないことの確認方法（警察届出用の説明資料）

> 作成: 2026-08-25。インターネット異性紹介事業の届出書に記載する
> 「児童でないことの確認の実施方法」の説明と文例（たたき台）。
> **行政書士の確認を経てから提出すること**（法的助言ではない）。
> 実装と一致した内容のみを記載している（ソースコード・DB制約で裏取り済み）。

## 1. ハピマリが実際に行っている確認（実装済みの事実）

| 段階 | 内容 | 技術的な裏付け |
|---|---|---|
| ① 登録時 | 生年月日の申告を必須とし、**35歳未満は登録自体を拒否**（18歳の法定基準を大きく上回る自主基準） | アプリ検証＋DB制約（`profiles_min_age_check`）の二重 |
| ② 書面確認 | **公的書類（運転免許証・マイナンバーカード・パスポート等、氏名と生年月日が確認できるもの）の画像**をアプリから送信させる | `(verification)/upload.tsx`・非公開ストレージ保存 |
| ③ 目視審査 | 運営が管理画面の審査キューで書類を確認し、承認して初めて「本人確認済み」になる | admin `verifications`・`review_verification`（審査者・日時を記録） |
| ④ 利用制限 | 確認完了まで**メッセージの送信・いいねの送信（一言メッセージ含む）・音声通話ができない**（いずれも画面制御ではなくサーバー側で強制。通話は双方の確認完了が必要） | メッセージ: `can_caller_message()`＝RLS＋トリガ ／ いいね: `like` 関数 ／ 通話: `agora-token` 関数（2026-08-26 変更） |
| ⑤ 再利用時 | メールアドレス＋パスワードによるログインで本人を識別 | Supabase Auth（規則でいう「識別符号の送信を受ける方法」に相当） |

## 2. 法令上の位置づけ

出会い系サイト規制法 施行規則が認める確認方法のうち、
**「運転免許証その他の年齢又は生年月日を証する書面に係る画像の電磁的方法による送信を受ける方法」**に該当する
（クレジットカード方式・マイナンバーカード電子証明書方式ではない）。
2回目以降は「識別符号を送信させる方法」による。

## 3. 届出書の記載文例（たたき台・行政書士の添削前提）

> 利用者の登録時に生年月日の申告を受け、システムにより35歳未満の者の登録を拒否する。
> さらに、運転免許証、個人番号カード、旅券その他の年齢又は生年月日を証する書面に係る
> 画像の電磁的方法による送信を受け、当社の審査担当者が当該書面の記載により
> 児童でないこと（あわせて当社の利用基準である35歳以上であること）を確認する。
> この確認が完了するまで、利用者は他の利用者へのメッセージの送信、いいね（短文の
> メッセージを含む。）の送信及び音声通話を行うことができない。
> 2回目以降の利用に際しては、確認を受けた利用者にのみ付与される識別符号
> （メールアドレス及びパスワード）の送信を受けることにより確認する。

## 4. 行政書士に必ず確認すべき点（実装との正直な突き合わせ）

1. **確認完了「前」に可能な操作は「プロフィールの閲覧」のみ**（2026-08-26 変更後）。
   いいねの送信・音声通話は同日付で「確認後のみ」に変更済み
   （`docs/decisions/2026-08-26_確認前操作の安全側変更.md`。変更前は確認前でも可能だった）。
   残る確認点: **確認前のプロフィール閲覧**が法第11条の確認タイミング
   （閲覧・伝達の前）との関係で問題ないか。業界大手も閲覧は確認前が通例と認識しているが、
   NGの場合は閲覧にも確認を課す改修を行う（工数は小さくない。要相談）。
2. **確認記録の作成・保存義務**への適合。現在は審査の承認/却下・審査日時・書類画像を保存している。
   法令上の記録項目・保存期間の要件と、退会後90日削除の保持方針（論点2）が両立するか。
3. **目視審査（eKYCなし）で足りるか**。SPEC上、自動照合は導入せず管理画面の目視審査が正式フロー。

## 5. 運用上の改善候補（未実施・オーナー承認があれば実施）

  書類の生年月日と登録値の突合が審査者の記憶頼みになっている）。小改修（1ファイル）。

## 7. 「18歳未満は利用できません」の表示状況と追加提案（法第10条の伝達・明示義務）

現状: アプリの入口2画面に「35歳以上が対象」の表示はあるが、**「18歳未満は利用不可」の明示はどこにも無い**。
LPには年齢の記載自体が無い。規約ドラフト（terms_of_service.md 第◯条）には18歳条項があるが、
LPのterms.htmlが仮文面のため**公開ページには未反映**。

追加提案（オーナー承認後に実施）:
1. LP全ページのフッター＋ファーストビュー付近: 「18歳未満の方はご利用いただけません。」
2. アプリ welcome: 「ご登録は35歳以上の方が対象です（18歳未満の方はご利用いただけません）」
3. アプリ signup の注意書きに同旨1行
4. LPの terms.html / privacy.html / tokushoho.html を正式文面（弁護士レビュー後）へ差し替え
